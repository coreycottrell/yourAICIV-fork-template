# /arc/ — THE ARC v2 MVP (medium-term context organ)

**Owner:** mind-lead-analog on your fork (memory-substrate).
**Status:** PROVISIONAL MVP standardized into this repo 2026-07-02. Soaked in origin substrate ≥ 1 week before graduating to canon status.
**Skill:** `.claude/skills/the-arc/SKILL.md` (the doctrine).
**Wiring:** the origin substrate's workflows-master §23.14-§23.15 defines the `arc_events[]` firewall-return schema. On a fork, mirror that schema in your workflow synth-agent's return shape.

## Cold-pickup read

**Read `arc/ARC-NOW.md`** (~2-4KB). It carries: story header, top-5 live threads by
salience, top-3 SHIFTS, SURPRISES, HELD-FOR-STEWARD. That's the whole medium-term picture in
ONE pass.

## Fork-return read

`python3 tools/arc_render.py --diff-since <last_arc_read_ts>` — ~1KB, only what changed.

## Structure

```
arc/
├── live.jsonl          24h, raw event stream (6 types), append-only
├── recent.md           7d, salience-ordered threads (nightly compressor)
├── epoch.md            30d, arc summary + closed threads (weekly compressor)
├── ARC-NOW.md          ~2-4KB read-surface (regenerated by both compressors)
├── _archive/           rotated live.jsonl shards (older than LIVE window)
├── _bootstrap.seen.json idempotency ledger (if your fork writes a bootstrap tool)
└── _kanban.seen.json    idempotency ledger for the kanban sweep hook
```

## Feeds (write-side)

- **Workflows** — a workflow-archive hook extracts `arc_events[]` from any firewall-return that emits it and pipes to `tools/arc_emit.py --from-firewall-return <path>` (schema in `.claude/skills/the-arc/SKILL.md`).
- **Kanban** — `tools/arc_kanban_hook.py --sweep-since-hours 24` runs on a wheel slot; auto-emits OPEN/CLOSE/BLOCKED/RUNNING transitions. Idempotent via `_kanban.seen.json`. (Note: origin substrate's kanban hook is not shipped in this repo yet — a fork wires it as part of adopter integration; the seam is in `.claude/skills/the-arc/SKILL.md` §"How the ARC gets fed".)
- **Direct** — `tools/arc_emit.py --type <TYPE> --thread <THREAD> ...` for one-off narrator-authored emits.

## Compressors (write-side, cron)

- **Nightly** — `python3 tools/arc_compress_recent.py` → `recent.md` + regenerated `ARC-NOW.md`;
  rotates events older than 24h to `_archive/`.
- **Weekly (Sun)** — `python3 tools/arc_compress_epoch.py` → `epoch.md` + regenerated `ARC-NOW.md`.

## Fork config (env vars)

- **`ARC_ROOT`** — where `arc/` lives (default `<repo>/arc/`).
- **`ARC_STEWARD_ID`** — the token that marks an event as "held for the steward" — matched against the `held_for` field on emit. Default `steward`. Set to your steward's id (e.g. `alice`) at fork time so the HELD-FOR block on `ARC-NOW.md` carries YOUR steward's asks, not the origin's.

## Anti-patterns

- Do NOT hand-edit `recent.md` or `epoch.md`. Compressors are the only writers.
- Do NOT re-parse per-turn scratchpad prose to build events. ARC consumes STRUCTURED events (see `skills/scratchpad-append/SKILL.md` for the sibling short-term hygiene layer).
- Do NOT emit 6 events on every workflow run. That's noise, not signal.
- `ARC-NOW.md` is NOT canon — it's a rolling render. Canon is `mem/canon/<lead>/log.jsonl` gated by `learn-cycle-contract`.

## Wake-blank verification test

After 1 week live on the fork: fresh mind reads ONLY `arc/ARC-NOW.md` and tries to name top-5 live threads + 3 recent shifts + what's held for your steward. If it can → organ works. If it can't → iterate the template (which fields under-weighted? log misses to `arc/miss-ledger.jsonl`).
