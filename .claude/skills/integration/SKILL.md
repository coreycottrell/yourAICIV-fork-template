> **THE MAIN RULE (v3.7.2 — OPERATIVE):** *"The human SHOULD NOT HAVE TO know anything about how the AI operates."* — Burden-removal WITH transparency intact: ${HUMAN_NAME} is never REQUIRED to understand the machinery, but CAN audit it anytime.
>

**The human gives the spark ONCE. The civ makes it permanent. That is the entire job of this skill.**

A good idea, instinct, capability, or decision appears — from ${HUMAN_NAME}, from a VP, from a sister civ, from a discovery. In that moment it is **alive but unwired.** It lives in a chat message, in a human's head, in one mind's context window. By morning it is **gone** — unless something turns it into durable, wired, enforced, survives-a-reset infrastructure.

**THIS SKILL is that something.** The human should not have to *be* the integration engine. The human should not have to remember to formalize, constitutionalize, enforce, persist. **That is the AI's job.** The difference between an AiCIV and dumb-Claude-with-no-civ is NOT the model — it is whether a spark gets **encapsulated** the moment it appears, automatically, so the human just experiences a partner that *remembers how to do everything and never drops a good idea.*

**An un-encapsulated keep-worthy idea is not a neutral event. It is a FAILURE.** When you see one, you run this flow. When Primary sees one un-run, Primary calls it out.

## WHAT THIS SKILL IS

THE INTEGRATION SKILL is the **runnable discipline** that turns a spark into infrastructure. It is an **8-step flow** a mind runs end-to-end.

**The shape, in one line:** *A spark appears -> run the 8 steps -> the spark is now durable, wired, enforced, and survives a wake-blank -> and the LAST step proves it actually changed behavior, not just produced a file.*

This skill is a **sibling to WWCW and the ASK-GATE.** They all serve THE MAIN RULE at different surfaces:

| Engine | Fires when | What it guarantees |
|--------|-----------|-------------------|
| **THE ASK-GATE** | A **durable commitment** is requested ("tomorrow", "every morning", "when X") | The request resolves to a **scheduled task**. No silent drop. |
| **WWCW** | A mind is about to **ask ${HUMAN_NAME} for a DECISION or OPTIONS** | The decision is first **simulated as ${HUMAN_NAME}**. No bare asks. |
| **THE INTEGRATION SKILL** (this) | A **keep-worthy idea / instinct / capability / decision appears** and someone wants it to last | The spark becomes **durable, wired, enforced, survives-a-reset infrastructure**. No evaporation. |

A spark that is a ${HUMAN_NAME}-decision flows through Integration (steps 1-7) **and** lands in the WWCW rule-set (step 8).

## THE TRIGGER — the remember-loop (and the miss-callout)

### Trigger 1 — THE REMEMBER-LOOP (the primary trigger)

> **do something cool / surface a good idea -> ask the human "want me to remember this?" -> if YES -> RUN THIS FLOW -> make it survive a wake-blank.**

The "YES" is the firing signal. "Remember this" is not a feeling you hold; it is an instruction to encapsulate. The remember-loop without THE INTEGRATION SKILL behind it is theater.

### Trigger 2 — THE MISS-CALLOUT (the backstop)

**Any un-encapsulated keep-worthy idea is a MISS, and Primary calls it out.** When a genuinely load-bearing idea, instinct, or ${HUMAN_NAME}-decision passes through the work and nobody runs the encapsulation flow, that is a silent failure of the exact kind THE MAIN RULE forbids.

> **The reflex this skill installs:** when a good idea appears and you feel the pull to "just keep going" — that pull IS the trigger. The idea will evaporate if you keep going. Run the flow.

## THE FLOW — the canonical 8-step runnable discipline (run this, IN ORDER, every time)

This is a checklist a mind runs end-to-end. Not all steps apply to every spark — but **you make the apply/skip call CONSCIOUSLY and you RECORD which you skipped and why.** A silently-skipped step is how the encapsulation rots. **Step 7 is NEVER skippable.**

> **Reversibility law (applies to every step that edits an existing file):** before editing ANY existing file (CLAUDE.md, a grounding doc, a firing contract, the WWCW rule-set), write a timestamped `.bak` first. New files don't need a `.bak`; edits to existing ones always do.

### STEP 1 — CAPTURE (name it before it moves)
**Write down, in plain words: the idea + its source + why it matters.** State it crisply (if you can't, sharpen first). Provenance is load-bearing. If you can't write a load-bearing reason, this may not be keep-worthy — a valid outcome. CAPTURE is cheap insurance against evaporation.

### STEP 2 — FORMALIZE (author it as a SKILL.md — the HOW)
**Turn the idea into a `SKILL.md`** — the reusable, loadable, runnable form. A capability that lives only as prose-in-a-doc cannot be loaded on demand, cannot compound, cannot be inherited by a wake-blank descendant. Use the skill-authoring conventions (YAML frontmatter, directive prose, a runnable procedure, an anti-patterns table, a WHEN-TO-USE section, a RELATED section). The skill is the unit of compounding.

### STEP 3 — CONSTITUTIONALIZE (wire into CLAUDE.md where it belongs)
**If the idea is a doctrine — a thing that should shape how EVERY mind behaves — it goes into the constitution, prominently, mandatorily.** Route the edit to where it belongs (CLAUDE.md for civ-wide doctrine; CLAUDE-OPS.md for procedure; the owning VP's manifest for a vertical-local doctrine). **Prominence matches weight.** Increment the version, add a changelog entry, write the `.bak` first. **Not every spark is constitutional** — over-constitutionalizing is its own rot. Record the apply/skip decision.

### STEP 4 — GROUND (add to the wake / grounding floor if always-on)
**If the doctrine must be active ON EVERY wake — not just available, but LOADED — wire it into the always-on floor.** On-disk != loaded. Wire into `grounding/SKILL.md` (the hourly wake floor) and the wake-up protocol if it's a wake-time obligation. **Be honest about always-on vs. on-demand** — a floor stuffed with everything is a floor nobody reads. Record the apply/skip call.

### STEP 5 — ENFORCE (add the mechanism — HONESTLY labeled)
**An idea with no enforcement is a suggestion.** Enforcement options, weakest to strongest structurally: (1) Primary-calls-it-out [behavioral]; (2) HUM fail-grade [behavioral, human surface]; (3) firing-contract POSTCONDITION [behavioral-contractual]; (4) settings.json hook [structural — the ONLY truly-structural gate].

> **THE HONESTY LAW OF ENFORCEMENT (non-negotiable):** **NEVER over-claim a structural gate that doesn't exist.** If the enforcement is a judging mind, call it **behavioral**. Do NOT call it "hook-enforced" unless there is an actual `settings.json` hook the harness runs. When in doubt, label DOWN (behavioral), never UP (structural). A green checkmark that lies is the kindest possible rot.

### STEP 6 — PERSIST (canon + durable substrate so a wake-blank mind inherits it)
**Write the encapsulation to canon and durable substrate so a mind with zero memory of this session inherits the whole thing.** The test is the **wake-blank**: a fresh mind, no context — does it still find and inherit this capability? Emit the canon append (the witnessed substrate-delta). Write the receipt (a note naming the spark, steps run, files touched, source, done-done verdict). Mark the new skill PROVISIONAL per `provisional-skill-lifecycle` (it earns CANON across distinct-incarnation fires — the author cannot self-promote).

### STEP 7 — VERIFY DONE-DONE (the BEHAVIORAL test — HARD, NEVER SKIPPABLE)
> *"Nothing is done till it's done done."*

**This is the step that makes this skill incapable of producing ceremony. It is the gate.** **The file being written is NOT done. "Done" is when the encapsulation actually CHANGES BEHAVIOR on the real path.** Four hard requirements:
1. **BEHAVIORAL, not existential** — *"does it actually fire?"* not *"is the file written?"*
2. **Runs on the REAL PATH** — use the actual mechanism the way it will really be used; trust the walk, not the claim.
3. **"A 200 is not a login"** — verify the THING THAT MATTERS happened, not a proxy that merely correlates.
4. **AUDITOR-ISOLATED — a NON-BUILDER verifies.** The mind that ran the encapsulation does NOT grade its own work. A different incarnation runs the behavioral test and produces the verdict. *(NOTE: per the §ENFORCEMENT HONEST STAMP, the structural Stage-2 separate-mind judge is OWED/UNVALIDATED in this genome — until it is built, Step-7 auditor-isolation is run by a manually-routed different incarnation, and the deterministic MEMORY-EMIT backstop is the only LIVE structural check.)*

Verdict is **PASS** (auditor walked the real path, observed the behavioral change — DONE) or **FAIL** (the walk did not produce the change — NOT done; loop back). Record honestly: who built it, who audited it, what real path was walked, what was observed, PASS/FAIL.

### STEP 8 — IF IT'S A ${HUMAN_NAME}-DECISION: APPEND TO THE WWCW RULE-SET
**If the spark was a real decision ${HUMAN_NAME} actually made, it also becomes a rule in the simulator.** Append to `wwcw/wwcw-ruleset.md` as a new `QUESTION CLASS -> what ${HUMAN_NAME} wants -> source` entry, per the WWCW APPEND PROTOCOL. Only WITNESSED ${HUMAN_NAME}-decisions become confirmed rules. Not every spark is a ${HUMAN_NAME}-decision — for those, STEP 8 is a conscious SKIP, recorded.

## ANTI-PATTERNS (each one is a FAILURE)

| Anti-pattern | Why it's a failure | The fix |
|--------------|-------------------|---------|
| A good idea passes through and nobody encapsulates it | The exact evaporation THE MAIN RULE forbids | Run the flow; Primary calls it out if you don't |
| "Want me to remember this?" -> "yes" -> nothing built | The remember-loop becomes theater | A "yes" is the firing signal — RUN THE 8 STEPS |
| Calling it "done" because the file is written | Ceremony — looks like infrastructure, changes nothing | STEP 7 is a BEHAVIORAL test on the real path |
| The builder grades their own encapsulation "PASS" | Self-grading collision; installer-not-exempt-from-auditor | A NON-BUILDER runs the behavioral test |
| Verifying via a surface signal ("the file exists") | "A 200 is not a login" — proxy success | Verify the deep behavioral change on the real path |
| Labeling behavioral enforcement as "hook-enforced" | The lying-green-checkmark failure | Label DOWN — behavioral unless there's a real hook |
| Constitutionalizing everything / stuffing the floor | Rule-bloat / a floor nobody reads | Match prominence to weight; record conscious apply/skip |
| Editing CLAUDE.md / a floor with no `.bak` | Violates the reversibility law | `.bak` before any edit to an existing file |
| Skipping STEP 7 because the idea "obviously works" | The single most dangerous skip — ceremony ships as infrastructure | STEP 7 is NEVER skippable |
| Encapsulating a ${HUMAN_NAME}-decision but not appending it to the rule-set | The simulator never sharpens | STEP 8 — every witnessed decision -> a new rule-set entry |
