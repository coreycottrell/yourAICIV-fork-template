# THE ARC — the living working-set (medium-term context organ)

**Read this ONE file to know how the arc works.** The whole doctrine collapses to: *the arc is the antechamber of canon; it holds the story while the story is still writing itself.*

---

## The one-line frame

> **Medium-term context is the ARC of an unfinished story — what's IN FLIGHT, what SHIFTED, what's TRENDING.** It's not a turn (too small, that's `scratchpad-append`). It's not a canon fact (too finished, that's the `mem/canon/*/log.jsonl` trunk gated by `learn-cycle-contract`). It's the shape of the last N days as a fork would need to *feel* it, not *read* it from prose.

---

## Where THE ARC sits in the memory tier stack

| Tier | Timescale | Skill | Storage | Discipline |
|---|---|---|---|---|
| **short** | this-turn | `scratchpad-append` | `.claude/scratchpad-daily/YYYY-MM-DD.md` | append prose per turn; hygiene, not centerpiece |
| **medium** | days-to-weeks | **`the-arc` (this skill)** | `arc/{live.jsonl, recent.md, epoch.md, ARC-NOW.md}` | append structured events; the CENTERPIECE |
| **long** | permanent | `learn-cycle-contract` + `canon_append` | `mem/canon/<lead>/log.jsonl` | witnessed substrate-delta with different-mind verifier |

**Steward directive 2026-07-02: SHIP BOTH.** The scratchpad-append is the per-turn hygiene layer — it keeps the running thought alive across auto-compact. The ARC is the centerpiece — it holds the STORY across days-to-weeks so a fork can rebuild medium-term context in ONE cold read (~2-4KB), not by re-parsing prose journals.

---

## When to load this skill

- **On every wake:** read `arc/ARC-NOW.md` (~2-4KB) as an early cold-pickup read. This is the medium-term picture in one pass.
- **On every fork-return within a session:** run `python3 tools/arc_render.py --diff-since <last_arc_read_ts>` (~1KB) — skip everything you already saw.
- **When authoring a workflow:** know that your firewall return can emit `arc_events: []` (schema-locked, ≤6/run) — this is how the arc gets fed. Emit only on real state change; over-emit dilutes salience worse than under-emit.
- **When touching kanban:** you don't call anything — `tools/arc_kanban_hook.py --sweep-since-hours <N>` runs on a wheel slot and auto-emits OPEN/CLOSE/BLOCKED/RUNNING transitions.

## Structure (three tiers + one read-surface)

```
arc/
├── live.jsonl          (~50KB, last 24h, append-only, structured events)
├── recent.md           (~20KB, last 7d, nightly compress, threads-by-momentum)
├── epoch.md            (~8KB, last 30d, weekly compress, arc-summary)
├── ARC-NOW.md          (~2-4KB, regenerated by both compressors — the ONE wake read)
└── _archive/           (rotated live.jsonl shards older than the LIVE window)
```

**Wake-read budget = ~2-4KB (`arc/ARC-NOW.md`).** Diff-read budget = ~1KB (`arc.diff --diff-since ...`).

## The 6-Event Schema

Every arc-event is one of six types:

| Type | Semantics | Base salience | Half-life |
|------|-----------|---------------|-----------|
| **SURPRISE** | The thing you didn't expect. Persists longest — we LEARN from surprises. | 1.00 | 21 d |
| **SHIFT** | X changed from A to B. This is what turn-transcripts BURY. | 0.90 | 14 d |
| **DECIDE** | A WWCW-eligible or steward-eligible fork was resolved. | 0.75 | 10 d |
| **VERIFY** | Trust-the-walk artifact-witnessed proof. Boosts ancestor threads +0.2 (v2.1). | 0.60 | 7 d |
| **CLOSE** | A thread ended (passed / abandoned / merged). | 0.55 | 5 d |
| **OPEN** | A thread became live. Extends via refcount (v2.1). | 0.35 | 3 d |

**Emit shape (JSONL row):**
```jsonl
{"ts":"2026-07-02T15:30Z","type":"SHIFT","thread":"pm-director","from":"design done","to":"v0.1 build started","who":"${HUMAN_NAME}","evidence":"TG 73147","confidence":"high"}
```

**Constraints (mirror `memory_delta.canon_appends[]` discipline):**
- Max 6 events per workflow firewall return. Same cap as canon_appends[].
- Max 200 chars per string field.
- `thread` field is MANDATORY (this is how compression groups events).
- `evidence` field MANDATORY for VERIFY / CLOSE.
- Emitting is CHEAP; over-emit is worse than under-emit (dilutes salience).

## How a fork rebuilds medium-term (one read)

```
1. Read arc/ARC-NOW.md  (~2-4KB, ~2 seconds)
   → Fork knows the story: top 5 live threads by salience, top 3 SHIFTS,
     top 3 SURPRISES, what is HELD FOR your steward (see ARC_STEWARD_ID
     env in arc_render.py — set it to your steward's id at fork time).

2. IF returning after a gap (any duration):
      python3 tools/arc_render.py --diff-since <last_arc_read_ts>   (~1KB)
   → Fork gets ONLY what changed since last read.

3. IF need thread depth: read arc/recent.md  (~20KB)
   ELSE done.

4. IF 5+ days blank: read arc/epoch.md  (~8KB)
   ELSE done.
```

## Salience (the smart part — MVP v2.0)

Every event carries a salience score. **`recent.md` is ordered by salience, not clock.**

```
# v2.0 (this MVP):
salience(event, t) = base(type) × exp(-ln2 · Δh / halflife(type))

# v2.1 (post-1-week soak — declared here, stubbed in code):
salience *= (1 + 0.15 · refcount_since)
salience *= (1 + 0.3 · verified?)
salience  = held_for_STEWARD ? max(0.6, salience) : salience   (pin)
```

The `held_for_STEWARD` pin uses env `ARC_STEWARD_ID` (default `steward`) — a fork sets this to its steward's id at fork time; the render pipeline then floats events pinned for that steward to the top of the HELD-FOR block regardless of decay.

## How the ARC gets fed (three write-paths)

### Path 1 — Workflow firewall returns (the primary feed)

Every Dynamic Workflow's synth-agent can emit `arc_events[]` as an OPTIONAL field on its firewall return. Same discipline as `memory_delta.canon_appends[]` — synthesis emits, VPs don't. The hook `.claude/hooks/workflow_emit_audit_log.py` (on a fork with a matching hook) extracts `arc_events` from the firewall return and feeds `arc_emit._append()` AFTER the archive-write completes. A broken arc feed CANNOT break the emit-log or the archive — fail-open.

### Path 2 — Kanban transitions (auto, idempotent)

`tools/arc_kanban_hook.py --sweep-since-hours 24` runs on a wheel slot. OPEN / CLOSE / BLOCKED / RUNNING transitions auto-emit ONE event each. Idempotency ledger at `arc/_kanban.seen.json`.

### Path 3 — Direct emit (one-off)

```bash
python3 tools/arc_emit.py --type SHIFT --thread pm-director \
    --from "design done" --to "v0.1 build started" \
    --who ${HUMAN_NAME} --evidence "TG 73147" --confidence high
```

Use for narrator-authored events not captured by workflows or kanban (rare — the two auto-paths cover most cases).

## Composition rules (no duplication)

- **vs SHORT (`scratchpad-append`):** the scratchpad is prose ("what am I doing right now?"); the ARC is structured events ("what story am I in?"). Scratchpad may reference arc-events by ID. **The ARC does NOT re-parse scratchpad prose** — it pulls from workflow firewall returns + kanban transitions + direct emits.
- **vs LONG (canon):** ARC = in-flight + rolling; canon = verified + permanent. `CLOSE + VERIFY` events are canon-append CANDIDATES through the `learn-cycle-contract` (different-mind verifier gated). **ARC → canon is one-way promotion.** Once a fact lands in canon, ARC-NOW references it by canon-id and the weekly compressor drops it from `recent.md` on next pass. **The ARC is the antechamber of canon.**
- **vs handoffs (if your fork keeps them):** handoffs remain human-narrative artifacts; `ARC-NOW.md` is the machine-generated complement.

## The single new discipline (author-level)

**When you author or amend a workflow, your firewall return schema gains one optional field:**

```typescript
arc_events?: Array<{
  type: "SHIFT" | "OPEN" | "CLOSE" | "DECIDE" | "VERIFY" | "SURPRISE"
  thread: string       // canonical thread name (e.g., "pm-director-v0.1")
  from?: string        // SHIFT
  to?: string          // SHIFT
  who?: string
  evidence?: string    // REQUIRED for VERIFY / CLOSE
  confidence?: "low" | "medium" | "high"
  goal?: string        // OPEN
  owner?: string
  kanban_id?: string
  decision?: string    // DECIDE
  wwcw?: "confident" | "uncertain"
  reason?: string      // CLOSE
  claim?: string       // VERIFY
  result?: "pass" | "fail"
  observation?: string // SURPRISE
  impact?: string
  held_for?: string    // "{steward-id}" pins salience (matches ARC_STEWARD_ID env)
}>  // max 6 events, each string field max 200 chars
```

Same discipline as `memory_delta.canon_appends[]`. Same enforcement path — the workflow substrate's synth-agent schema enforces `additionalProperties:false` + `maxItems: 6` + per-field `maxLength: 200`.

**When you touch kanban:** you don't call anything. The kanban hook auto-emits on state change.

## Verification (the wake-blank test)

**After 1 week live**, do the wake-blank test:

1. Fresh fork reads ONLY `arc/ARC-NOW.md`.
2. Fork tries to name: top 5 live threads + 3 recent shifts + what's held for its steward.
3. **If it can** → the organ works. Promote to canon-status.
4. **If it can't** → iterate the template (which fields under-weighted? what surprised the fork after read?). Log the miss to `arc/miss-ledger.jsonl`; the v2.4 miss-refit script uses those to tune the salience formula.

**Then:** repeat weekly. The miss-ledger is the honest record of when the organ under-served a real fork.

## Anti-patterns (things to NOT do)

1. **DO NOT** re-parse per-turn scratchpad prose to build arc events. The ARC consumes STRUCTURED events (workflow firewall returns + kanban transitions + direct emits), NOT prose. If it's not worth emitting a structured event, it's not worth tracking at medium-term.
2. **DO NOT** over-emit. If every turn produces 6 events, the ledger becomes noise and salience decays uniformly. Emit only on real state change. Most workflow runs emit 0-2 events.
3. **DO NOT** hand-write `recent.md` or `epoch.md`. Compressors are the ONLY writers. Hand-writing breaks the self-runs-itself property.
4. **DO NOT** treat `ARC-NOW.md` as canon. It's a rolling render. Canon lives in `mem/canon/<lead>/log.jsonl` and is gated by `canon_append.py` + `learn-cycle-contract`.
5. **DO NOT** emit an OPEN and a CLOSE in the same firewall-return (unless the thread genuinely opened and closed inside the workflow run). Salience math already handles short-lived threads; the noise isn't worth it.
6. **DO NOT** emit arc_events for every VP inside a workflow. The SYNTH agent emits the small digest, not each VP — same discipline as `memory_delta.canon_appends[]`.

Delete `arc/` + revert the workflow firewall-return schema field. No other organ depends on the ARC (it composes downstream from everything). `scratchpad-append` keeps working. `learn-cycle-contract` keeps working. `HUM` keeps working. The mind loses medium-term recall but the heartbeat survives.

**The ARC is additive, not load-bearing on the heartbeat.** Ship it. Soak it. Verify the wake-blank test. If it doesn't earn its keep, revert cleanly.
